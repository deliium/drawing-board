# README marketed heuristic recognition as AI / calibrated confidence

**Date:** 2026-09-08 17:34
**Files:** README.md, .ai-factory/plans/http-websocket-perimeter-security.md, internal/docguard/readme_honesty_test.go, internal/docguard/doc.go
**Severity:** low

## Problem

`/aif-verify` on the HTTP/WebSocket perimeter plan flagged leftover README marketing that described the handwriting recognizer as “AI-powered” / “AI Recognition” and presented scores as “confidence”, contradicting Task 8 and the Japanese-learning product constraints (heuristic recognizer must not be labeled AI; scores are not calibrated confidence).

## Root Cause

Perimeter docs (ALLOWED_ORIGINS, CSRF, proxy) were updated in Prompt 03 Task 8, but pre-existing feature overview and Recognition System sections were left unchanged. Those sections predated the honesty constraint and overstated ONNX as an active ML accuracy upgrade even though model load is not implemented.

## Solution

Rewrote README recognition copy to describe heuristic pattern-based ranking and match scores explicitly, and documented that the ONNX path currently falls back to the simple recognizer. Softened setup comments so `ONNX_MODEL` / `make onnx-model` are not presented as an immediate accuracy upgrade. Noted the follow-up on the perimeter plan Task 8 checkbox. Added `internal/docguard` Go test that greps README for banned AI/confidence marketing phrases (`go test ./internal/docguard`).

## Prevention

- When a plan says “do not describe X as Y”, grep the full README (not only newly added sections) before marking docs tasks complete.
- Treat product constraints about recognition honesty as a cross-cutting docs check on every plan that touches README.
- Defer deep ONNX/strategy rewrite to Prompt 08, but never leave “AI” / calibrated-confidence claims in shipping docs.
- Keep `go test ./internal/docguard` green; extend `forbiddenREADMEPatterns` if new overselling phrases appear.
