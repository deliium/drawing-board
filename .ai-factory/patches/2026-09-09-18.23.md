**Date:** 2026-09-09 18:23
**Files:** web/tests/helpers/stubCanvasContext.ts, web/tests/unit/practice-journey.spec.ts, web/tests/unit/practice-components.spec.ts, web/tests/integration/practice-journey-hiragana5.spec.ts
**Severity:** low

## Problem

`/aif-verify` on Prompt 13 flagged non-blocking gaps: submit/assess failure and empty-stroke resume paths were implemented but untested; ComparisonOverlay mounts logged jsdom `getContext` not-implemented noise (and could throw once a partial stub was introduced).

## Root Cause

1. Happy-path and load-error coverage landed first; S3 empty-ink resume and S4 submit/assess failure were left as code-only.
2. jsdom has no real canvas; overlay `paint()` calls `getContext` → `drawTraceTemplates` needs at least `save`/`restore`.

## Solution

- Add unit tests for empty-stroke resume notice, submit 5xx → freewrite, assess 429 → submitting + `retryAssess`.
- Add integration submit-failure case.
- Shared `stubCanvasContext` helper mocks a minimal 2d context (`[FIX]` debug log) for overlay mounts.

## Prevention

- When `/aif-verify` lists scenario gaps (S3/S4), add table-driven or focused Vitest cases in the same change set as the journey code.
- Any jsdom mount that paints canvas should reuse `stubCanvasContext` (include `save`/`restore`) rather than relying on not-implemented warnings.
