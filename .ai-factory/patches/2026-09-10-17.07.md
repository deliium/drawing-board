# UUID cutover left numeric attempt IDs in contract tests

**Date:** 2026-09-10 17:07
**Files:** web/tests/contract/attempts-api.spec.ts, go.mod, go.sum
**Severity:** medium

## Problem

`/aif-verify` on UUID primary keys failed `make check-web`: Vitest passed, but `tsc --noEmit` reported TS2345 because `attempts-api.spec.ts` still passed numeric attempt IDs (`3`, `7`, `9`) into APIs typed as `string`. `github.com/google/uuid` was also listed as `// indirect` despite direct imports.

## Root Cause

Task 8 partially updated fixtures (mock JSON used UUIDs) but left call-site arguments and path expectations as legacy integers. Runtime Vitest does not enforce TypeScript parameter types, so the gate that catches this is `npm run typecheck` / `npm run build`, not `npm test` alone.

## Solution

Replace numeric attempt IDs with the same UUID fixtures used elsewhere in the suite; assert paths with those UUID strings. Promote `github.com/google/uuid` to a direct `require` via `go get` + `go mod tidy`.

## Prevention

- After entity-ID type changes, run `make check-web` (typecheck + test + build), not Vitest alone.
- Grep call sites for `\(\d` on ID-taking helpers (`getAttempt`, `submitAttempt`, `assessAttempt`, WS `delete`) in the same change set as the type migration.
- Prefer shared UUID fixture constants when updating contract mocks and call arguments together.
