# Unused hitTest import broke web TypeScript build

**Date:** 2026-09-08 18:44
**Files:** web/src/composables/usePracticeCanvas.ts
**Severity:** low

## Problem

`/aif-verify` failed on `npx tsc --noEmit` / `npm run build` with TS6133:
`hitTest` is declared but its value is never read in `usePracticeCanvas.ts`.

## Root Cause

Eraser hit-testing was intentionally left in `BoardPage.vue` (`onEraseAt` → `hitTest` → `removeStrokeLocally`), but the composable still imported `hitTest` from an earlier sketch of in-composable erase. The unused import was never exercised, so unit tests passed while the production `tsc && vite build` path failed.

## Solution

Removed the unused `hitTest` import from `usePracticeCanvas.ts`. Runtime erase behavior unchanged (BoardPage still hit-tests). No `[FIX]` runtime log — this was a compile-time dead import with no execution path to instrument.

## Prevention

- After extracting helpers into a composable, run `npx tsc --noEmit` (or `npm run build`) before marking verify green — Vitest alone does not enforce `noUnusedLocals`.
- Prefer importing symbols only at the call site that uses them (BoardPage for erase hit-test; composable for pointer lifecycle).
- When wiring callbacks (`onEraseAt`) instead of inlining helpers, delete leftover imports in the same change.
- Regression: `web/tests/unit/practice-canvas.spec.ts` → `practice canvas erase ownership` asserts composable does not import `hitTest` while BoardPage does.
