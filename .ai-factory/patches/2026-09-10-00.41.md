# Feature flags not refreshed after login/register

**Date:** 2026-09-10 00:41
**Files:** web/src/pages/LoginPage.vue, web/tests/unit/auth-page.spec.ts
**Severity:** medium

## Problem

Guest bootstrap leaves feature flags at the all-on default because `GET /api/features` is auth-only and `main.ts` only loads flags when `/api/me` succeeds. After login or register, the SPA navigated to the board without refreshing flags, so kill switches (`FEATURE_PRACTICE` etc.) stayed incorrectly on until a full page reload.

## Root Cause

`loadFeatureFlags()` was wired only into the authenticated bootstrap path. LoginPage set the session and routed to `board` without re-fetching `/api/features`, assuming bootstrap had already populated the cache.

## Solution

After a successful login/register, await `loadFeatureFlags()` before `router.replace({ name: 'board' })`, with DEV `[FIX]` logging of the refreshed flags. Soft-fail behavior in `loadFeatureFlags` is unchanged (keeps last/default on error).

## Prevention

- Any auth success path that creates a session must refresh auth-gated client mirrors (features, and similar) before navigating into gated routes.
- Cover login → `/api/features` ordering in Vitest so regressions fail when the second call is dropped.
